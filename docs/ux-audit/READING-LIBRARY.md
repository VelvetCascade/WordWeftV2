## Verification

- `npm run typecheck`: passed.
- `npm test`: 200 passed, zero failures.
- Focused Maven suite at a 384 MiB heap: 55 passed, zero failures/skips, covering `LibraryOrganizationControllerTest`, `PassageBookmarkServiceTest`, `ChapterContentControllerTest`, `ChapterContentServiceTest`, `ContentAccessServiceTest`, `CharacterServiceAccessTest`.
- Browser commands use `E2E_BASE_URL=http://127.0.0.1:3003`, native `/usr/bin/chromium`, and one worker. The disposable Spring API uses port 8080 and the disposable OTP mail sink uses 8081. API tests create isolated local accounts; they do not mutate production.
- Pending-typing regression first failed with the newer textarea replaced by the submitted first note; after the edit-version guard it passed, including closing/reopening and saving/reloading the newer note.
- Nested quote regression first failed to focus an unchanged saved outer quotation; after authored HTML extraction it passed for quotation/list anchors and search. Backend assertions confirm matching canonical quotes, including inline adjacency and `br` boundaries.
- A pre-restart browser run passed 23/24. The sole failure was owner shelf deletion against the backend process started before `7f89d85`; the updated backend passed that case in the final broad run.
- Final broad browser run after the backend restart: 33/34 passed across `quality-reading-library`, `reader-async-actions`, `reader-formatted-content`, `reader-route-state`, `reading-progress` and `reader`. The sole failure was an obsolete `Paragraph #3` accessible-name selector in the existing reader test. Updating it to the implemented `Passage 3` name made the focused failed-post/draft/retry case pass 1/1. All 34 distinct browser cases have passing evidence; the 34-case command itself returned one failure before that test-only correction.

## Captures and limits

All seven committed captures were inspected: desktop prose/discussion; phone library, resume, shelves and passage tools; and the private-note editor at 390×480 with its Save action reachable by sheet scrolling. Axe checks use WCAG 2 A/AA and 2.1 AA on the opened passage, discussion, shelf, library and preferences surfaces. Covers in the local fixture use the existing fallback presentation.

Chromium viewport/touch emulation and a short viewport do not verify a physical iPhone keyboard, Safari/Chrome, native VoiceOver, translation or read-aloud. Ordinary readable DOM and access-boundary checks establish the implementation path, not those native-tool outcomes. Unsaved passage notes are retained only in this tab's memory; the UI requires saving online before closing the browser. Cross-device concurrent private-note editing is outside this follow-up's verification.
